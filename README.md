# وب‌سایت شخصی وکیل — فارسی، راست‌چین، تک‌صفحه‌ای

یک وب‌سایت تک‌صفحه‌ای، کاملاً فارسی و راست‌چین (RTL) برای معرفی و وکیل. سبک، سریع و بدون هیچ فریم‌ورک سنگینی؛ فقط HTML + CSS + جاوااسکریپت خالص — بنابراین روی GitHub Pages بدون هیچ تنظیم خاصی اجرا می‌شود.

## ویژگی‌ها

- کاملاً فارسی و RTL
- تک‌صفحه‌ای با اسکرول نرم بین بخش‌ها
- واکنش‌گرا (موبایل، تبلت، دسکتاپ، دسکتاپ بزرگ)
- بدون وابستگی خارجی (بدون CDN، بدون node_modules در خروجی)
- فونت وزیرمتن به‌صورت محلی (خود-میزبان)
- آیکن‌های SVG درون‌خطی (بدون درخواست اضافه)
- پشتیبانی `prefers-reduced-motion`
- دسترس‌پذیری: منوی کیبوردی، فوکوس مشخص، aria-labels، HTML معنایی
- سئو: متاتگ‌ها، Open Graph، ساختار معنایی
- تمام محتوا از یک فایل پیکربندی مرکزی (`js/config.js`) خوانده می‌شود

## ساختار پروژه

```
├── index.html          ← قالب اصلی (بخش‌ها و متاتگ‌ها)
├── css/
│   ├── style.css       ← استایل اصلی
│   └── extras.css      ← ادامه استایل (فرم، فوتر، پاسخگویی، حرکت کم)
├── js/
│   ├── config.js       ← ✨ تمام متن‌ها و داده‌ها — همین جا را ویرایش کنید
│   └── main.js         ← رندر محتوا + تعاملات (منو، اسلایدر، فرم، آکاردئون)
├── assets/
│   ├── fonts/          ← فونت وزیرمتن (woff2)
│   └── img/            ← تصاویر (جای تصویر پروفایل و تصویر ثانویه)
├── build.mjs           ← ساخت خروجی تولیدی (بدون وابستگی)
├── serve.mjs           ← سرور محلی کوچک برای پیش‌نمایش
└── package.json
```

## نصب

نیازی به نصب وابستگی نیست؛ فقط Node.js نسخه‌ی ۱۸ یا بالاتر برای دستورهای build/serve لازم است.

```bash
# بررسی Node
node -v
```

## اجرای محلی

```bash
npm start
# یا
node serve.mjs
```

سپس مرورگر را در آدرس `http://localhost:8080` باز کنید.

## ساخت (Build)

```bash
npm run build
# یا
node build.mjs
```

خروجی در پوشه‌ی `dist/` ساخته می‌شود (مینیفای سبک و بدون وابستگی). برای پیش‌نمایش خروجی تولیدی:

```bash
npm run preview
# یا
node serve.mjs dist
```

## استقرار روی GitHub Pages

۱. پروژه را به GitHub پوش کنید.
۲. در ریپازیتوری به مسیر زیر بروید:
   `Settings → Pages`
۳. در بخش *Branch*، شاخه‌ی `main` و پوشه‌ی ریشه (`/ (root)`) را انتخاب کنید و ذخیره کنید.

> نکته: کل وب‌سایت ایستا و بدون مرحله‌ی ساخت سرور است؛ فایل‌های ریشه مستقیماً منتشر می‌شوند. اگر خواستید نسخه‌ی `dist/` را منتشر کنید، فایل‌های داخل `dist/` را در ریشه‌ی ریپازیتوری یا یک شاخه‌ی جداگانه قرار دهید.

## جای تغییر محتوا — همه‌چیز در `js/config.js`

تمام متن‌های وب‌سایت (به‌جز تگ‌های متا در `index.html`) از فایل `js/config.js` خوانده می‌شوند. این فایل را باز کنید و بخش‌های زیر را ویرایش کنید:

| چه چیزی | کجا در config.js |
| --- | --- |
| نام، تلفن، ایمیل، آدرس، ساعات کاری، واتساپ | `lawyer` |
| لینک‌های منو و دکمه‌ی CTA | `nav` |
| متن و دکمه‌های هرو | `hero` |
| آمار اعتماد (سال سابقه، پرونده‌ها و…) | `stats` |
| متن «درباره من» | `about` |
| حوزه‌های تخصصی فعالیت | `practiceAreas` |
| سوابق حرفه‌ای (گاه‌شمار) | `experience` |
| تجربه و زمینه‌های حرفه‌ای | `legalExperience` |
| دلایل «چرا من را انتخاب کنید؟» | `whyChooseMe` |
| نظرات موکلین | `testimonials` |
| سوالات متداول (FAQ) | `faq` |
| متن و دکمه‌های فراخوان مشاوره | `cta` |
| کارت‌های تماس و فیلدهای فرم | `contact` |
| متن‌های فوتر، اعلان قانونی و کپی‌رایت | `footer` |

### جایگزینی تصاویر

- تصویر بخش اول (هرو): فایل را در `assets/img/` قرار دهید و مسیر را در `hero.image` در `js/config.js` بنویسید (مثلاً `assets/img/lawyer-hero.svg`). متن و دکمه‌های واقعی به‌صورت شفاف روی تصویر نمایش داده می‌شوند.
- تصویر پروفایل (در صورت استفاده از چیدمان بدون تصویر هرو): در `lawyer.portrait`.
- تصویر ثانویه‌ی بخش «درباره من»: در `lawyer.secondaryImage`.

### اتصال فرم تماس به سرویس ارسال پیام

فرم به‌صورت پیش‌فرض به‌صورت شبیه‌سازی‌شده کار می‌کند (بدون backend). برای اتصال به سرویس واقعی:

1. آدرس endpoint را در `contact.form.formEndpoint` در `js/config.js` قرار دهید.
2. تابع `submitConsultationRequest()` در `js/main.js` درخواست POST با JSON می‌فرستد؛ می‌توانید آن را با API دلخواه خود جایگزین کنید.

> هیچ رازی (API key یا ایمیل) در کد جلویی قرار نمی‌گیرد؛ سرویس‌دهنده باید اعتبارسنجی و محدودسازی نرخ ارسال را انجام دهد.

### تنظیم نقشه‌ی گوگل

لینک embed نقشه را در `contact.map.embedUrl` قرار دهید. تا زمانی که خالی باشد، یک قاب جایگزین نمایش داده می‌شود.

## نکات مهم (پیش از انتشار)

- تمام مقادیر فعلی **نمونه و جایگزین‌پذیر** هستند؛ پیش از انتشار، اطلاعات واقعی وکیل (نام، شماره پروانه، سوابق، آمار) را جایگزین کنید.
- تگ‌های متا و آدرس canoncal در `index.html` را به‌روز کنید.
- ساختار داده‌ی Schema.org را فقط پس از تأیید اطلاعات واقعی اضافه کنید (نمونه به‌صورت کامنت در `index.html` موجود است).
- نام موکلین در نظرات بدون اجازه نمایش داده نشود.
